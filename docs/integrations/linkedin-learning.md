## English

**LinkedIn Learning**

The LinkedIn Learning courses the centre is licensed for, and the learners' activity reports, to see who completed a course and count its hours in the record.

### What the provider gives you

- [ ] A LinkedIn Learning contract with enterprise (site) licences, and an administrator account in the Admin Settings
- [ ] The Learning API enabled for the application (LinkedIn must allow it; without it the token request answers access_denied)
- [ ] The application's Client ID and Client Secret from the Admin Settings (LinkedIn Developers portal)
- [ ] The reporting API (learningActivityReports) enabled for the application's keys
- [ ] Learners provisioned with a uniqueUserId that is the employee number (or the same e-mail address TEDC has)
- [ ] Single sign-on configured so ssoLaunch links are returned and the learner opens a course without a second sign-in
- [ ] TEDC's outbound addresses allowed to reach api.linkedin.com and www.linkedin.com on port 443

### What is set up in TEDC

Open the card and fill in the settings below, then press “Check connection”. Then compare the shipped contract and mapping with the provider's document in the Contract tab and edit what differs (every save is a version you can go back to).

| Setting | Secret | Default | Notes |

| `base_url` |  | `https://api.linkedin.com/v2` | The address of LinkedIn's API (the default is right). |

| `client_secret` | yes |  | The client secret the provider gives. |

| `locale_language` |  |  | Catalogue language: de en es fr in it ja ko pl pt tr zh (empty: what the licence gives). There are no Arabic courses. |
| `locale_country` |  |  | Catalogue country, such as US. |
| `completions_lookback_days` |  | `7` | How many days back each nightly check looks for completions (a provider's reports can arrive late). |
| `default_hours` |  |  | The hours counted for a course when the provider states no duration. |

**Authentication in the shipped contract:** OAuth2 client credentials — the token comes from `https://www.linkedin.com/oauth/v2/accessToken`, the client signs in with the request form, and the token is presented as `Bearer <token>`.

| `list_completions` — Learners' activity and course completions | `GET /learningActivityReports` | yes |
| `health` — Connection check | `GET /learningAssets` | yes |
