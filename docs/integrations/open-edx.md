**منصة Open edX**

دورات منصة Open edX التي تراها حسابات الخدمة، وشهادات المتعلمين فيها لمعرفة من أتمّ الدورة واحتساب ساعاتها في السجل.

### ما يقدّمه المزوّد

- [ ] عنوان منصة Open edX (LMS) كما يراه المتعلمون، مثل https://lms.example.org

- [ ] Client ID وClient Secret للتطبيق
- [ ] اسم حساب الخدمة الذي تُسرد دورات المنصة بصلاحياته (username)
- [ ] شهادات المنصة مفعّلة في دوراتها (تُقرأ الشهادات المجتازة فقط)، وصلاحية قراءتها لحساب الخدمة (certificates:read)
- [ ] اسم المستخدم في المنصة هو الرقم الوظيفي (الافتراضي)، أو البريد الإلكتروني؛ عبر الدخول الموحد أو حسابات أُنشئت لهذا الغرض
- [ ] السماح لعناوين TEDC الصادرة بالوصول إلى المنصة عبر المنفذ 443

## English

**Open edX**

The courses of an Open edX platform that the service account can see, and the learners' certificates, to see who completed a course and count its hours in the record.

### What the provider gives you

- [ ] The address of the Open edX platform (the LMS) as learners see it, such as https://lms.example.org
- [ ] An OAuth application (Django OAuth Toolkit) of the “client credentials” type created in the admin portal /admin/oauth2_provider/application/, owned by a staff service account
- [ ] The application's Client ID and Client Secret
- [ ] The username of the service account whose visible courses are listed
- [ ] Certificates are enabled in the courses (only passing ones are read), and the service account may read them (certificates:read)
- [ ] The username on the platform is the employee number (the default) or the e-mail address, through single sign-on or accounts made for this
- [ ] TEDC's outbound addresses allowed to reach the platform on port 443

### What is set up in TEDC

Open the card and fill in the settings below, then press “Check connection”. Then compare the shipped contract and mapping with the provider's document in the Contract tab and edit what differs (every save is a version you can go back to).

| Setting | Secret | Default | Notes |
|---|---|---|---|
| `base_url` |  |  | The address of your Open edX platform (the LMS) as learners see it. |
| `client_id` |  |  | The client id (the app key) the provider gives. |
| `client_secret` | yes |  | The client secret the provider gives. |
| `username` |  |  | The Open edX service account whose visible courses are listed. |
| `org` |  |  | Only the courses of this organization (optional). |
| `username_source` |  | `employee_no` | What an employee's username on the platform is: the employee number, the e-mail address, or the part before the @. |
| `token_url` |  |  | Only to point at a mock or a proxy; empty uses the provider's own token service. |
| `completions_lookback_days` |  | `7` | How many days back each nightly check looks for completions (a provider's reports can arrive late). |
| `default_hours` |  |  | The hours counted for a course when the provider states no duration. |

**Authentication in the shipped contract:** OAuth2 client credentials — the token comes from `the path /oauth2/access_token`, the client signs in with the Authorization header (Basic), and the token is presented as `JWT <token>`.
