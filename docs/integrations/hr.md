## English

**HR system**

Employees and their job data from the HR system, and the routing of profile change requests to it.

### What the Ministry provides

- [ ] The system address (test environment first, then production)
- [ ] The authentication type and credentials (key, account or certificate)
- [ ] TEDC's outbound addresses added to the Ministry allow-list
- [ ] Real sample requests, responses and error codes
- [ ] A test account or test data for the joint session
- [ ] The employee list path (full, and changes since a date), its fields, and the job title, school and department codes
- [ ] The path that receives profile change requests and how acceptance and refusal come back
- [ ] The signing secret of the answer that comes back (webhook) and how it is signed

| Setting | Secret | Default | Notes |

| `health_path` |  | `/health` | The path of the connection check; it answers success when the system is well. |

| `client_id` |  |  | The client id at the token service. (Used when the contract signs in with: oauth2) |

**Authentication in the shipped contract:** a bearer token in the Authorization header (optional: left out when not set).

**Operations:**

| Operation | Request | Read-only |
|---|---|---|
| `fetch_employees` — Employee list | `GET {{ settings.employees_path\|default:/employees\|raw }}` | yes |
| `send_profile_change` — Send a profile change request | `POST /profile-changes` |  |
| `health` — Connection check | `GET {{ settings.health_path\|default:/health\|raw }}` | yes |

**Messages coming in from the system:**

- Signature: header `X-TEDC-Signature`, hmac-sha256, hex, time in `X-TEDC-Timestamp` (up to 300 seconds old)
- Message number (so a repeat is harmless): `Idempotency-Key` / `$.id`
