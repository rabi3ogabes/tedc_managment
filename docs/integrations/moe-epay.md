## العربية

**بوابة الدفع الإلكتروني للوزارة**

الدفع عبر صفحة البوابة المستضافة: بدء الدفع، التحقق من النداء الموقَّع، الاسترداد، وكشف الحساب للمطابقة. لا تمرّ بيانات البطاقة بـ TEDC.

### ما تقدّمه الوزارة

- [ ] عنوان النظام (بيئة التجربة ثم الإنتاج)
- [ ] نوع المصادقة وبيانات الاعتماد (مفتاح أو حساب أو شهادة)
- [ ] السماح لعناوين TEDC الصادرة في قائمة الوزارة المسموحة
- [ ] أمثلة حقيقية لكل طلب واستجابة وأكواد الأخطاء
- [ ] حساب أو بيانات تجريبية للاختبار المشترك
- [ ] مواصفات البوابة الرسمية: مسارات بدء الدفع والاسترداد والكشف، وحقول الطلب والاستجابة، وأكواد الحالة
- [ ] رقم التاجر (Merchant ID) والسر المشترك أو زوج المفاتيح (خاص/عام) وخوارزمية التوقيع
- [ ] صيغة المبلغ (منزلتان أو ثلاث، بالريال أو بالدرهم) ورمز العملة ولغة الصفحة المستضافة
- [ ] بيئة تجريبية للبوابة مع بطاقات اختبار لكل حالة (نجاح، رفض، إلغاء)
- [ ] تسجيل عنوان النداء الموقَّع لدى البوابة وقائمة العناوين الصادرة منها للسماح بها

### اختبارات الإطلاق مع الوزارة

شغّل هذه الحالات من تبويب «حالات الاختبار» أولًا على الإجابات المسجّلة، ثم على النظام الفعلي (القراءة فقط) بحضور الوزارة:

| الحالة | العملية | النتيجة المتوقعة |
|---|---|---|
| A payment starts and the buyer is sent to the hosted page | `initiate` | الطلب POST /payments; القيم: payment_id=P-1001, redirect_url=https://pay.moe.example/redirect/P-1001 |
| The gateway refuses the merchant credentials | `initiate` | خطأ واضح: unauthorised |

| The day's statement maps to captured and failed payments | `statement` | الطلب GET /transactions; السجلات: 2 |

## English

**Ministry e-payment gateway**

Payment on the gateway's hosted page: starting a payment, the signed callback, refunds and the statement for reconciliation. Card data never passes through TEDC.

### What the Ministry provides

- [ ] The system address (test environment first, then production)
- [ ] The authentication type and credentials (key, account or certificate)
- [ ] TEDC's outbound addresses added to the Ministry allow-list
- [ ] Real sample requests, responses and error codes
- [ ] A test account or test data for the joint session
- [ ] The gateway's official specification: the start, refund and statement paths, the request and response fields and the status codes
- [ ] The merchant id, the shared secret or the key pair, and the signing algorithm
- [ ] The amount format (two or three decimals, riyals or dirhams), the currency code and the language of the hosted page
- [ ] A sandbox with test cards for each outcome (success, decline, cancellation)
- [ ] The signed callback address registered with the gateway, and the addresses it calls from

### What is set up in TEDC

Open the card and fill in the settings below, then press “Check connection”. Then compare the shipped contract and mapping with the Ministry's document in the Contract tab and edit what differs (every save is a version you can go back to).

| Setting | Secret | Default | Notes |
|---|---|---|---|
| `base_url` |  |  | The system's address (https) as the Ministry gives it, without a path. |
| `merchant_id` |  |  | The merchant id at the payment gateway. |
| `secret` | yes |  | The shared secret that signs requests and the gateway's callbacks (HMAC). |
| `health_path` |  | `/health` | The path of the connection check; it answers success when the system is well. |
| `private_key` | yes |  | RSA: TEDC's private key (PEM) that signs requests; the Ministry keeps the public half. |
| `callback_key` |  |  | RSA: the Ministry's public key (PEM) that checks the gateway's callbacks. |

**Authentication in the shipped contract:** an HMAC/RSA signature on every request.

**Operations:**

| Operation | Request | Read-only |
|---|---|---|
| `initiate` — Start a payment | `POST /payments` |  |
| `refund` — Refund (full or partial) | `POST /payments/{{ payment_id }}/refund` |  |
| `statement` — The day's transactions | `GET /transactions` | yes |
| `health` — Connection check | `GET {{ settings.health_path\|default:/health\|raw }}` | yes |

**Messages coming in from the system:**

- Signature: header `X-Signature`, hmac-sha256, hex

- Switching the integration off on the card stops every call at once and deletes nothing in TEDC.
- Go back to a previous version of the contract or mapping from Contract → Versions (it adds a new version equal to the old one), or “Reset to shipped” for what comes with TEDC.
- Switching to the training mode (driver: fake) returns the system to sample data with no outside connection.
- [ ] The rollback plan agreed: switch the integration off, or return to the previous contract version
