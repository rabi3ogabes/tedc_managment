## English

**Coursera for Business**

The courses and specializations in the centre's Coursera learning programs, and the learners' completions, so their hours count in the record.

### What the provider gives you

- [ ] A Coursera for Business agreement, and an administrator account of the organization
- [ ] The organization id, shown at the top of the organization's admin settings page
- [ ] An app registered in the developer portal (dev.coursera.com) with the organization's admin account, with the Coursera Business API enabled
- [ ] The app key (client id) and its secret
- [ ] At least one learning program with the courses the centre will offer
- [ ] Learners invited or signed in with an external id that is the employee number or the e-mail address: it is how completions are matched to employees
- [ ] TEDC's outbound addresses allowed to reach api.coursera.com on port 443

### What is set up in TEDC

Open the card and fill in the settings below, then press “Check connection”. Then compare the shipped contract and mapping with the provider's document in the Contract tab and edit what differs (every save is a version you can go back to).

| Setting | Secret | Default | Notes |
|---|---|---|---|
| `base_url` |  | `https://api.coursera.com/ent` | The address of Coursera's API platform (the default is right). |
| `org_id` |  |  | The organization id, shown at the top of the organization's admin settings page at Coursera. |
| `client_id` |  |  | The client id (the app key) the provider gives. |
| `client_secret` | yes |  | The client secret the provider gives. |
| `token_url` |  |  | Only to point at a mock or a proxy; empty uses the provider's own token service. |
| `completions_lookback_days` |  | `7` | How many days back each nightly check looks for completions (a provider's reports can arrive late). |
| `default_hours` |  |  | The hours counted for a course when the provider states no duration. |

**Authentication in the shipped contract:** OAuth2 client credentials — the token comes from `https://api.coursera.com/oauth2/client_credentials/token`, the client signs in with the Authorization header (Basic), and the token is presented as `Bearer <token>`.

**Operations:**

| `health` — Connection check | `GET /api/businesses.v1/{{ settings.org_id }}` | yes |
