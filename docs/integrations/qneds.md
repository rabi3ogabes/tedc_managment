## English

**Qatar National Educational Data System (QNEDS)**

Aggregated training indicators per school: no names, no personal data.

### What the Ministry provides

- [ ] The system address (test environment first, then production)
- [ ] The authentication type and credentials (key, account or certificate)
- [ ] TEDC's outbound addresses added to the Ministry allow-list
- [ ] Real sample requests, responses and error codes
- [ ] A test account or test data for the joint session
- [ ] The indicator intake path, the indicators required, their formats and how often
- [ ] The school codes in use (the Ministry number), to match TEDC's

### What is set up in TEDC

Open the card and fill in the settings below, then press “Check connection”. Then compare the shipped contract and mapping with the Ministry's document in the Contract tab and edit what differs (every save is a version you can go back to).

| Setting | Secret | Default | Notes |
|---|---|---|---|
| `base_url` |  |  | The system's address (https) as the Ministry gives it, without a path. |
| `api_key` | yes |  | The key or token TEDC signs in with. |
| `health_path` |  | `/health` | The path of the connection check; it answers success when the system is well. |
| `inbound_secret` | yes |  | The secret the system signs its messages to TEDC with (or its public key, for an RSA signature). |
| `auth_header` |  |  | The header (or parameter) the key travels in, when the contract leaves it to the settings. (Used when the contract signs in with: api_key) |
| `username` |  |  | The user name. (Used when the contract signs in with: basic) |
| `password` | yes |  | The password. (Used when the contract signs in with: basic) |
| `token_url` |  |  | The address that issues access tokens (client credentials). (Used when the contract signs in with: oauth2) |
| `client_id` |  |  | The client id at the token service. (Used when the contract signs in with: oauth2) |
| `client_secret` | yes |  | The client secret at the token service. (Used when the contract signs in with: oauth2) |
| `signing_secret` | yes |  | The secret that signs every request. (Used when the contract signs in with: hmac) |
| `client_certificate` | yes |  | The client certificate (PEM) for mutual TLS. (Used when the contract signs in with: mtls) |
| `client_key` | yes |  | The private key of the client certificate (PEM). (Used when the contract signs in with: mtls) |

**Authentication in the shipped contract:** a bearer token in the Authorization header (optional: left out when not set).

**Operations:**

| Operation | Request | Read-only |
|---|---|---|
| `publish_indicators` — Publish the yearly indicators | `POST /indicators` |  |
| `health` — Connection check | `GET {{ settings.health_path\|default:/health\|raw }}` | yes |

- Go back to a previous version of the contract or mapping from Contract → Versions (it adds a new version equal to the old one), or “Reset to shipped” for what comes with TEDC.
- Switching to the training mode (driver: fake) returns the system to sample data with no outside connection.
- [ ] The rollback plan agreed: switch the integration off, or return to the previous contract version
