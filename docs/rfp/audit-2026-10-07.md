# Full-platform audit — 7 October 2026

Scope: every screen reachable from the menus (administration and portal, 7 roles), the public site, the help centre and e-kits, the API against the web and mobile callers, permissions, translations (Arabic / English), the PDF and Word outputs, CI and deployment.
Method: automated sweeps in a real browser (every menu entry and every settings tab: errors, failed requests, spinners that never end, redirects), static cross-checks (translation keys, routes, permissions, API calls, route shadowing), rendering of the generated PDFs, then the full test suite and CI.

A change that was wrong and was reverted: granting a new `logs.manage` permission made the error log visible to the centre administrator. The tests caught it; the log stays with the system administrator by design (test added to say so).

## Checked and found sound
* Arabic and English translation files have identical keys (7,114 each); no key used by the web app is missing; the mobile app's 692 strings match in both languages and every used key exists.
* All 1,130 API routes load; `route:cache` works (no closures); no route is shadowed; every permission used by a route exists (one intentional exception above); every web and mobile API call that can be resolved statically maps to a route.
* All menu entries of the 7 tested roles (system admin, centre admin, coordinator, school administrator, trainer, executive, kit developer, plus a trainee in the portal) open without errors, failed requests or endless spinners; all settings tabs; the public pages; no horizontal scrolling at 375 px.
* Flags on (payments, gamification, communities, forums): all their screens and tabs open.
* The two e-kits complete as a trainee through the real endpoints.

## Not verifiable here (stated, not hidden)
* The Flutter app runs only in CI (analyze + unit tests): no screen of it was opened. Static checks (routes, strings) are clean.
* Nothing was run against PostgreSQL locally (CI's Postgres job is green), Azure, an LMS, or the Ministry systems.
* Forms were exercised through the API tests and a sample in the browser (help-article editor); not every form of every phase was filled by hand in the browser.
* Uploading a video through the serverless host is limited by the host's request size (about 4.5 MB): use the video link field for longer videos.
